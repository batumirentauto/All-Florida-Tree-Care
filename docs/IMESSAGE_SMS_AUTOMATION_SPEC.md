# Техническое задание (ТЗ): Автоматизированная рассылка через iMessage и SMS

## 1. Цель проекта
Создание фонового скрипта на Python для контролируемой, безопасной и органичной рассылки персонализированных сообщений американским подрядчикам по уходу за деревьями (базы `new_scrape` и `tree_leads`) через приложение **«Сообщения» (Messages.app)** на macOS.

---

## 2. Ключевая логика каналов доставки

### 2.1. Сценарий A: Номер поддерживает iMessage (`Наличие iMessage == 'Да'`)
1. **Тип доставки:** Синий нативный пузырь iMessage (через Apple Push Notification Service).
2. **Вложение:** Прикрепляется оптимизированный мобильный скриншот сайта из папки:  
   `screenshots/mobile/{slug}_mobile_en.png` (размер до 950 КБ).
3. **Последовательность отправки:**
   - Шаг 1: Отправка изображения (получатель сразу видит Retina-превью сайта компании).
   - Шаг 2: Пауза 2–3 секунды (для успешной подгрузки медиафайла на серверах Apple).
   - Шаг 3: Отправка персонализированного текста (Вариант 1, 2, 3 или 4) с именем владельца и техникой.

### 2.2. Сценарий B: Номер НЕ поддерживает iMessage (`Наличие iMessage == 'Нет'`)
1. **Тип доставки:** Зеленый пузырь SMS через спаренный iPhone (Text Message Forwarding).
2. **Вложение:** **Категорически без картинок и ссылок** (только чистый текст). Это предотвращает сбои на операторских MMS-шлюзах (T-Mobile / AT&T / Verizon Cloudmark).
3. **Текст:** Отправляется выбранный текстовый вариант с соблюдением лимитов длины SMS.

---

## 3. График отправки и учет часовых поясов США

Скрипт обязан проверять текущее локальное время в штате адресата перед отправкой:

| Штаты в базе | Часовой пояс | Разрешенное окно отправки |
| :--- | :--- | :--- |
| **FL, GA, SC, NC, DE, VA** | Eastern Time (EST / EDT) | 09:30 – 17:30 (локальное время) |
| **TX, AL, MS, TN, IL** | Central Time (CST / CDT) | 09:30 – 17:30 (локальное время) |
| **CO, AZ, NM, UT** | Mountain Time (MST / MDT) | 09:30 – 17:30 (локальное время) |
| **CA, OR, WA** | Pacific Time (PST / PDT) | 09:30 – 17:30 (локальное время) |

* **Правило паузы:** Если в регионе подрядчика еще ранее 09:30 или позже 17:30, скрипт приостанавливает отправку для этого контакта и либо переходит к контактам из других часовых поясов, либо ждет наступления утра.
* **Выходные дни:** Возможность отключения рассылки в субботу и воскресенье.

## 4. Защита от блокировок Apple ID и спам-фильтров (Human Behavior Emulation)

1. **Плавающие интервалы (Jitter):**
   - Случайная пауза между сообщениями: **от 75 до 195 секунд** (1.25 – 3.25 минуты).
2. **Пакетные перерывы (Batch Cool-down):**
   - После каждых **10–12 отправленных сообщений** скрипт делает длинный перерыв на **12–20 минут**.
3. **Дневные лимиты (Daily Safety Cap):**
   - Максимум **35–50 сообщений в сутки** на один Apple ID.
   - По достижении лимита скрипт корректно завершает работу до следующего рабочего дня.
4. **Рандомизация текстов:**
   - Возможность чередования столбцов `Сообщение 1`, `Сообщение 2`, `Сообщение 3`, `Сообщение 4` для разных компаний во избежание монотонного текста.

## 5. Идемпотентность и ведение журнала (Log & Status Tracking)

В таблицы `companies.csv` и `companies.xlsx` добавляются служебные столбцы:
- **`Статус отправки`:**
  - `Ожидает`
  - `Отправлено (iMessage)`
  - `Отправлено (SMS)`
  - `Ошибка: [причина]`
  - `Пропущено (нет номера)`
- **`Дата и время отправки`:** ISO timestamp (например, `2026-10-22 11:42:15 EST`).
- **`Использованный вариант текста`:** `Вариант 1` / `Вариант 2` и т.д.

> [!IMPORTANT]
> При любом сбое или перезапуске скрипта уже обработанные строки пропускаются — повторная отправка исключена.

## 6. Технический стек и архитектура исполнения

- **Язык:** Python 3.
- **Интеграция с macOS:** Вызовы AppleScript через `subprocess.run(['osascript', ...])`.
- **Поддерживаемые режимы запуска:**
  - `--dry-run`: Эмуляция без реальной отправки сообщений (проверка таймзон, подстановки данных, наличия скриншотов).
  - `--limit N`: Отправка тестовой пачки из $N$ сообщений.
  - `--service [imessage|sms|all]`: Выбор конкретного канала.
  - `--variant [1|2|3|4|random]`: Выбор шаблона сообщения.
